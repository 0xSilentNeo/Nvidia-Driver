# MT7925 for macOS

A native macOS (IOKit) driver for the MediaTek MT7925 Wi-Fi 7 PCIe card
(also MT7927 and MT7928), built by running the **unmodified Linux `mt76`
driver** on top of a Linux-kernel-API compatibility layer for IOKit, the way
FreeBSD runs the same driver through its LinuxKPI.

> **Status: foundation.** Nothing here has run on a Mac yet. The vendored
> driver compiles front-end clean against the compatibility layer, the OS
> boundary is defined, and the IOKit kext and C runtime are being written.
> See `docs/ROADMAP.md` for what is checked and what is not.

> **AirDrop is not a goal this project can promise.** It needs Apple's
> proprietary AWDL protocol, which no third-party macOS Wi-Fi driver has ever
> delivered. Everything else native (menu bar, System Settings, Handoff,
> Universal Clipboard, Instant Hotspot) is on the plan. Read `docs/AIRDROP.md`
> before deciding whether this project is for you.

## Why this approach

| Alternative | Problem |
|---|---|
| Write a MT7925 driver from scratch | The MCU protocol, firmware download and DMA descriptors are thousands of lines of vendor-specific, frequently updated code. |
| Port OpenBSD's driver (the itlwm route) | OpenBSD has no MT7925 driver. |
| Run Linux mt76 through a compatibility layer | Proven by FreeBSD (`sys/contrib/dev/mediatek/mt76` + LinuxKPI); FreeBSD needed under 60 one-line edits across the whole mt76 tree. Upstream fixes land by re-importing. |

Licensing works out cleanly: mt76 is BSD-3-Clause-Clear, FreeBSD's 802.11
API headers are BSD-2-Clause, and this project's code is MIT. No GPL code is
used (Linux's own mac80211/cfg80211 headers are GPL and are replaced by the
FreeBSD re-implementations).

## Layout

```
src/mt76/            Linux mt76 driver, verbatim, pinned (src/mt76/UPSTREAM)
src/linuxkpi/        Linux kernel API on IOKit (C)
  include/linux,net  our headers + FreeBSD's 802.11 API headers (pinned)
  include/lkpi/os.h  the single C ABI to the OS
  src/               runtime: locks, work, timers, kthreads, rcu, skbuff,
                     page pool, napi, idr, pci, dma, devres, firmware, printk
src/kext/            MT7925.kext: IOService on IOPCIDevice + os.h backend (C++)
src/lkpi80211/       FreeBSD's mac80211->net80211 glue, reference for phase 3
patches/             our edits to vendored files, regenerated by scripts
scripts/             import/pin upstream, fetch firmware, API inventory
tests/host/          libc backend for os.h + unit tests (runs on Linux/macOS)
docs/                ARCHITECTURE, ROADMAP, AIRDROP, LINUX_API_INVENTORY
```

## Building and checking

On any machine with clang (no Apple SDK needed):

```sh
make check-headers   # front-end compile of the driver + C layer, must be all ok
make link-check      # compile to host objects, list symbols the kext must still supply
make inventory       # regenerate docs/LINUX_API_INVENTORY.md
make host-tests      # unit tests of the C layer against the libc os.h backend
```

On a Mac with the Xcode command line tools:

```sh
scripts/fetch-firmware.sh      # downloads the MediaTek blobs into firmware/
make kext                      # builds build/MT7925.kext (see src/kext/README.md)
```

Loading an unsigned kext requires reduced security (SIP/kext consent on real
Macs, OpenCore kext injection on Hackintosh systems). The kext README covers
it.

## Supported hardware

PCI IDs matched (vendor `14c3`): `7925`, `0717` (MT7925), `7927`, `6639`,
`0738` (MT7927), `7928`, `7935` (MT7928). USB and SDIO variants are not
supported. The Bluetooth half of these modules is a separate USB function and
needs a separate driver.

## Updating the vendored driver

```sh
scripts/import-mt76.sh            # clone upstream, copy the PCIe source set
scripts/import-freebsd.sh         # refresh the 802.11 API headers
scripts/apply-patches.sh          # re-apply our hunks
make check-headers                # fix fallout, then
scripts/regen-patches.sh          # rewrite patches/ from the result
```

## Contributing

Keep the three rules that make this maintainable:

1. Never edit `src/mt76/**` or the FreeBSD-derived headers directly without
   regenerating `patches/`; prefer fixing the compatibility layer.
2. C code under `src/linuxkpi` reaches the OS only through `lkpi/os.h`; C++
   code under `src/kext` never includes a Linux header.
3. `make check-headers` must stay at zero warnings.
